# Apple Music 网页版流体背景 · 实现解析与验证

> **研究对象**：`music.apple.com` 网页版「全屏播放器」动态流体背景（四层旋转封面 → 漩涡扭曲 → 递减 Box 模糊 → 色彩调校 → 半透明罩层）。
> 本文档系统梳理逆向分析方法、渲染管线拆解、核心参数依据及常见复现偏差排查。配套单文件实现见 [`demo/index.html`](../demo/index.html)。

## 2. 渲染管线架构

Apple 官方实现基于 PixiJS：在一个 `Container` 中挂载 4 层专辑封面 `Sprite`，容器整体绑定一条多级滤镜链；舞台最底层放置一块不透明白色矩形，渲染管线最顶层则覆盖一层全屏半透明罩层。

在原生 WebGL 复刻实现中，上述结构被拆解为 4 个渲染 Pass：

```text
Pass 1 · 场景合成   4 层封面精灵写入 FBO；以纯白 (1,1,1,1) 清屏；切歌时旧精灵立即移除，新精灵以 α ±0.02/帧淡入
Pass 2 · 漩涡扭曲   应用 TwistFilter 公式：在作用半径内按 ((r - d) / r)² × angle 旋转采样坐标
Pass 3 · 递减模糊   将 5 级模糊链 (5,1)(10,1)(20,2)(40,2)(80,2) 展开为 7 道递减 Box 核全分辨率 Pass（见 §3.1）
Pass 4 · 调色罩层   AdjustmentFilter（sat 2.75 / con 1.9 / bri 0.7）→ clamp [0,1] → 叠加黑 50% + 白 5% 罩层 → 输出屏幕
```

### 2.1 精灵层几何与运动参数（Apple 线上原值）

| 层标识 | 尺寸（× 视口参考宽） | 初始中心位置 | 基础角速度（/ 33.33ms） | 运动模式 |
|---|---|---|---|---|
| `t` | `1.25` | 视口中心 `(w/2, h/2)` | `+0.003` | 原地自转 |
| `s` | `0.80` | `(w/2.5, h/2.5)` | `−0.008` | 原地自转 |
| `i` | `0.50` | 视口中心 `(w/2, h/2)` | `−0.006` | 自转 + 公转（轨道半径 `w/4`，公转角速度 = 自转 × `0.75`） |
| `r` | `0.25` | 中心偏移 `(0.05w, 0.05w)` | `+0.004` | 自转 + 公转（轨道半径 `w/4`，公转角速度 = 自转 × `0.75`） |

> 当系统开启 `prefers-reduced-motion: reduce` 时，四层基础速度统一降为 `0.001`（公转小精灵的显示自转仍保持取负号规则）。

## 3. 七项关键实现细节深度解析

以下 7 项细节均通过对照 Apple 线上渲染脚本逐行核对得出，是决定复刻效果能否高度还原的核心分水岭：

### 3.1 模糊算法：内嵌 v4 系 BlurFilter（递减 Box 核）

官方管线中使用的并非 `pixi.js` v7 默认的 `BlurFilter`，而是打包内嵌的 **v4 系实现**（混淆标识符 `Ee`，内部维护 `uOffset` 与 `_kernels`）：

- **采样核结构**：每道 Pass 仅在 4 个对角象限角点采样并求均值（Box 核），采样偏移量为 `offset = kernels[p] + 0.5` 纹素；
- **递减序列**：给定强度 `blur` 与质量 `quality (q)`，生成的核序列为递减等差数列：`kernels = [blur, blur - blur/q, blur - 2·blur/q, ...]`；
- **实际展开链**：官方配置 `(strength, quality) = (5,1)(10,1)(20,2)(40,2)(80,2)` 共展开为 **7 道全分辨率 Pass**，对应采样偏移分别为：
  `5.5` → `10.5` → `20.5, 10.5` → `40.5, 20.5` → `80.5, 40.5`；
- **视觉成因**：递减步长的 Box 扩散会在大幅度柔和色彩的同时保留独特的**中频色块过渡**，这正是官方「水墨晕染」质感的核心算法来源；使用等效高斯模糊替代会丢失该层次感。

### 3.2 AdjustmentFilter 完整调色参数

色彩调校并非仅提高饱和度（`saturation = 2.75`），而是同时配合了 `contrast = 1.9` 与 `brightness = 0.7`。官方着色器公式（`gamma = 1.0`）如下：

```glsl
vec3 luma = vec3(dot(vec3(0.2125, 0.7154, 0.0721), rgb));
rgb = mix(vec3(0.5), mix(luma, rgb, saturation), contrast) * brightness;
```

### 3.3 切歌转场：白底淡入机制

切换曲目时，官方并未采用前后两套流体的交叉淡化（Cross-fade），而是：
1. **立即移除**旧曲目对应的精灵组；
2. 在舞台底层的**不透明白色矩形**上，将新曲目精灵以每帧 `±0.02` 的透明度逐步淡入（完整过程约 `1.65s`）；
3. 经过末段黑/白罩层压缩后，视觉上表现为画面从浅灰色底平稳浮现。

### 3.4 全屏罩层与 `[0, 1]` 色阶截断

在滤镜链输出之上，官方叠加了一层 `black 50% + white 5%` 的全屏半透明罩层，等效线性变换为：

```glsl
rgb = clamp(rgb, 0.0, 1.0);
rgb = rgb * 0.475 + 0.05;
```

- **动态范围压缩**：罩层将画面动态范围压缩近半，大幅降低了高对比度带来的锐利边界，这是**漩涡结构在视觉上被柔化、不易察觉**的直接原因；
- **截断顺序至关重要**：在 PixiJS 独立 Pass 架构中，`AdjustmentFilter` 写入 8-bit 中间纹理时会自动将 RGB 截断至 `[0, 1]`。若不在罩层前显式执行 `clamp(rgb, 0.0, 1.0)`：
  - 暗部区域被高对比度推至负值，会抵消后续 `+0.05` 的白底提升；
  - 高饱和亮部以 `> 1.0` 的数值进入罩层，会导致亮场严重过曝。

### 3.5 公转精灵的「逆行自转」与 15fps 帧率节流

- **逆行自转（Retrograde Rotation）**：两个处于轨道公转中的小精灵（`i`、`r`），其实际渲染旋转角取了负号（`sprite.rotation = -rot`）。自转方向与公转方向相反，使纹理相对于运动轨道产生「翻滚」效果，显著增强了流体动感；若忽略该负号，小精灵会呈现出机械式的刚性旋转；
- **15fps 节流**：官方显式设置 `ticker.maxFPS = 15`（实测帧率约 `14.9fps`）。较低的刷新率赋予了背景轻微的步进黏稠感，同时通过 `deltaMS / 33.33` 进行时间步长补偿，确保旋转角速度不随帧率降低而变慢。

### 3.6 离屏 Filter Frame 边界扩展

PixiJS 滤镜在计算时会自动将渲染区域（Filter Frame）按精灵包围盒与滤镜 `padding`（`Σ kernels ≈ 229px`）向外扩展。结合 `TwistFilter` 在视口上下边缘的采样偏移（可达屏外约 `373px`），官方管线在屏幕边缘模糊时采样的是**屏外真实渲染内容**。

复刻实现中，所有中间 FBO 四周均预留了 `M = 384px` 的扩展边距（Margin），并在最后一个 Pass 输出到默认帧缓冲时通过 UV 窗口裁剪回视口尺寸。

### 3.7 40×40 低分辨率缩略图输入源 ★

在 Apple 网页版 `backdrop` 组件中，传入场景的封面纹理并非高清原图，而是经过如下参数请求的超小缩略图：

```js
Go(artwork.url, { width: 40, height: 40, crop: 'bb', fileType: 'webp' })
```

将 `40×40` 的低分辨率色板放大数十倍铺满全屏，从源头上消除了所有高频纹理细节，形成纯净的色彩区块。**这是实现官方「水墨晕染感」最决定性的因素**——其重要性甚至高于模糊算法本身。若直接传入 `600×600` 原图，高频图像细节会穿透模糊链，导致最终视觉结构与官方效果产生明显偏差。

## 5. 常见复现偏差与排查清单

| 常见偏差现象 | 根本原因 | 解决方案 |
|---|---|---|
| 画面残留明显图像细节或色块边界过硬 | 直接使用了 `600×600` 等高清原图作为纹理输入 | 渲染前先将封面纹理下采样至 **`40×40`** |
| 色彩过饱和、亮暗反差过于刺眼 | 缺少全屏 `black 50% + white 5%` 罩层，或未在罩层前 `clamp` | 在 `AdjustmentFilter` 后先 `clamp(rgb, 0.0, 1.0)`，再应用 `rgb * 0.475 + 0.05` |
| 画面明暗层次与官方不符 | `AdjustmentFilter` 仅设置了饱和度，遗漏对比度与亮度 | 补全 `contrast = 1.9` 与 `brightness = 0.7` |
| 色彩扩散呈普通高斯模糊感，缺少水墨层次 | 使用标准高斯模糊替代了递减 Box 模糊链 | 按 4 对角纹素采样 + 递减 `kernels` 实现 7 道 Box Pass |
| 小色块呈机械刚性旋转，缺乏流体翻滚感 | 公转小精灵（`i`/`r`）的显示旋转角未取负号 | 对索引 `k >= 2` 的精灵应用逆行自转（`-rot`） |
| 动画过于顺滑，缺少原版的黏稠步进质感 | 未限制刷新率，以显示器原生 `60Hz+` 运行 | 启用 `15fps` 渲染节流并保留 `dt` 时间补偿 |
| 漩涡扭曲方向与大精灵自转方向对抗 | WebGL FBO（Y 轴向上）与 Pixi 屏幕系（Y 轴向下）坐标系手性相反 | 传入 `TwistFilter` 的角度需取反（`-angle`）对齐旋向 |
| 画面四边出现暗边、黑框或裁切伪影 | 离屏 FBO 尺寸仅等于视口，边缘采样越界触发 `CLAMP_TO_EDGE` | FBO 四周增加 `384px` Margin，末段 Pass 再按 UV 窗口裁剪输出 |

## 6. 单文件 WebGL 实现说明

[`demo/index.html`](../demo/index.html) 采用零依赖原生 WebGL 实现完整管线：

- **四段式管线**：`compositePass`（精灵顶点变换与 Premultiplied Over 混合）→ `twistPass`（基于全 Frame 尺寸的漩涡扭曲）→ `blurPass`（7 道递减 Box 模糊，末段集成调色与罩层输出）；
- **Margin Frame 机制**：所有离屏 FBO 均按 `(W + 768) × (H + 768)` 分配，末段通过 `u_uv0` 与 `u_uvScale` 精确裁剪回视口区域；
- **交互与调参**：内置实时参数面板（默认值与线上版本完全一致），支持本地图片文件选择、拖拽及剪贴板粘贴；
- **跨域纹理处理**：在线预设封面通过 `crossOrigin = 'anonymous'` 绘制至离屏 Canvas 后上传纹理，避免 WebGL 纹理污染（Tainted Canvas）。
