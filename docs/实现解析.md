# Apple Music 网页版流体背景 · 实现解析与验证

> 对象：music.apple.com 网页版「全屏播放器」的动态流体背景（四层旋转封面 → 扭曲 → 模糊 → 调色 → 罩层）。
> 本文整理实现分析过程、每一步的依据，以及复刻时最容易踩的坑。配套实现见 [`demo/index.html`](../demo/index.html)。

## 2. 渲染管线（对照 Apple 线上渲染脚本逐行核对）

Apple 侧的结构：一个 PixiJS `Container` 挂 4 层封面 `Sprite`，容器上挂一条滤镜链，舞台最底层是一块不透明白色矩形，最后整个特效之上还有一层全屏罩层。复刻时对应为 4 个 WebGL pass：

```
pass1 合成   4 层精灵画进 FBO；白底 clear；换歌 = 旧精灵瞬间移除、新精灵 alpha 每帧 ±0.02 淡入
pass2 扭曲   TwistFilter 公式：半径内按 ((r-d)/r)² × angle 旋转采样坐标
pass3 模糊   Apple 滤镜链 (5,1)(10,1)(20,2)(40,2)(80,2) → 7 道递减 box 模糊（见 §3.1）
pass4 调色   AdjustmentFilter（sat 2.75 / con 1.9 / bri 0.7）→ clamp → 叠黑 50% + 白 5% 罩层 → 屏幕
```

### 2.1 精灵层参数（原值）

| 层 | 尺寸（× 视口宽） | 初始位置 | 转速（/33.33ms） | 运动 |
|---|---|---|---|---|
| t | 1.25 | 屏幕中心 | **+0.003** | 原地自转 |
| s | 0.8 | (w/2.5, h/2.5) | **−0.008** | 原地自转 |
| i | 0.5 | 屏幕中心 | **−0.006** | 自转 + **公转**（半径 w/4，角速度 = 自转 × 0.75） |
| r | 0.25 | 中心偏 (0.1w, 0.1w) | **+0.004** | 自转 + **公转**（同上） |

`prefers-reduced-motion` 时四层速度全部降为 ±0.001。

## 3. 七处公开资料未覆盖的实现细节

以下均与 Apple 线上渲染脚本逐行核对得出，是「复刻得像不像」的分水岭：

### 3.1 模糊的真身：5 个内嵌 v4 系 BlurFilter（递减 box 核）

不是 pixi.js v7 的 `BlurFilter`，而是 Apple 打包内嵌的 v4 系实现（`uOffset` + `_kernels`）：

- 每 pass 只采 **4 个对角角点**求平均（box 核）：`offset = kernels[p] + 0.5` 纹素；
- `kernels = [blur, blur−blur/q, blur−2blur/q, …]` **递减**序列（q = quality）；
- 链 `(strength, quality) = (5,1)(10,1)(20,2)(40,2)(80,2)` 展开为 **7 道全分辨率 pass**：
  `5.5 / 10.5 / 20.5,10.5 / 40.5,20.5 / 80.5,40.5`；
- 递减 box 扩散的独特之处是**保留中间频**——这才是「水墨晕染」质感的真正来源。
  等效高斯链（包括我们先前的实现）出不来这个手感。

### 3.2 AdjustmentFilter 完整参数

不止 saturation 2.75，还有 **brightness 0.7 + contrast 1.9**。官方公式（gamma=1）：

```glsl
rgb = mix(vec3(0.5), mix(luma, rgb, saturation), contrast) * brightness;
```

### 3.3 换歌行为

旧精灵**瞬间移除**（无流体间交叉淡化），新精灵在舞台白色底矩形上以每帧 ±0.02 的透明度淡入（≈1.65s），经罩层后观感是「从浅灰浮现」。

### 3.4 全屏罩层：黑 50% + 白 5%

流体特效之上还叠了一层 `black 50% + white 5%` 罩层，动态范围被压掉一半——**这是 Apple 的漩涡「看不太出来」的直接原因**。复刻式：`rgb = rgb * 0.475 + 0.05`。
注意顺序：Adjustment 输出先 **clamp 到 [0,1]** 再叠罩层（Pixi 写 8-bit 中间纹理时天然截断）。

### 3.5 公转精灵的「逆行」+ 15fps 节流

- 两个公转小精灵的**显示自转取负号**（`i.rotation = -o.rotation`）：自转与公转方向相反，texture 相对轨道「翻滚」，是水流感来源之一；公开还原版漏了这个负号（会变成刚性转盘）；
- `ticker.maxFPS = 15`：流体背景只有 15fps 更新（实测 14.9fps），步进的「黏稠感」本身就是原版质感的一部分。dt 补偿照常累积，转速不会因节流变慢。

### 3.6 滤镜链 frame 出屏扩展

Pixi 滤镜的 frame = 精灵 AABB + padding（Σ kernels ≈ 229px），因此**画面边缘的模糊采的是屏外真实内容**；twist 的边缘采样可达屏外 ~373px。复刻时 FBO 四边各加 margin（本实现取 384px），末段 pass 再裁剪回视口。

### 3.7 ★ 封面纹理是 40×40 的 webp 缩略图

Apple 的 backdrop 组件：

```js
Go(artwork.url, { width: 40, height: 40, crop: 'bb', fileType: 'webp' })
```

传给场景的**不是封面原图，而是 40×40 的缩略图**。40×40 色板放大 40 倍 = 天然无内部细节的纯色彩晕染——这是「水墨感」的最终来源，比模糊算法更重要。
喂 600×600 原图时，细节会穿透模糊层，观感立刻「不一样」。我们初次 A/B 对不上色调与结构，最后就栽在这一条上。

## 4. 参数总表（Apple 原值）

| 参数 | 值 |
|---|---|
| 精灵层数 / 尺寸 | 4 层，视口宽 × 1.25 / 0.8 / 0.5 / 0.25 |
| 转速 | +0.003 / −0.008 / −0.006 / +0.004（每 33.33ms） |
| 公转 | 半径 w/4，角速度 = 自转 × 0.75，显示自转取负 |

## 5. 复现误区清单

1. **喂原图**（最常见）：细节穿透模糊层，直接「不像」——必须先缩到 40×40；
2. 缺黑/白罩层：色彩过艳、动态范围过大，一眼假；
3. Adjustment 只做饱和度：缺 contrast 1.9 / brightness 0.7，明暗结构不对；
4. 用等效高斯代替递减 box：质感从「水墨」变「普通高斯模糊」；
5. 公转精灵不取负号：纹理刚性旋转，没有「翻滚水流感」;
6. 跑 60fps：太顺滑，失去原版 15fps 的黏稠步进感；
7. twist 角度不按坐标系取负：旋涡逆着自转拧，水流观感拧巴（Pixi 采样系 y 向下，FBO y 向上）；
8. 忘记滤镜 frame 出屏扩展：画面四边出现暗边/裁切痕迹。

## 6. demo 实现说明

`demo/index.html` 为单文件原生 WebGL 实现（无 Pixi 依赖）：

- pass1 合成（精灵顶点变换 + 预乘 over）→ pass2 twist → pass3 模糊链 → pass4 末段调色 + 罩层输出；
- FBO 均带 384px margin 复刻 frame 出屏扩展，末段按 uv 窗口裁剪回视口；
- 面板可实时调整全部 Apple 参数（默认即原值），支持拖拽 / 粘贴本地图片当封面；
- 在线封面通过 `fetch` 转 blob 进 canvas，避免纹理污染。
